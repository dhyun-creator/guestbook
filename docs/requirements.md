## 1. 개요

누구나 이름 또는 별명을 입력하여 자유롭게 글을 남길 수 있는 방명록 기능을 제공한다.
회원가입 없이 글마다 비밀번호를 설정하여, 작성자 본인만 자신의 글(및 답글)을 수정·삭제할 수 있도록 한다.
방명록 글에는 다른 사람이 답글을 달 수 있으며, 답글도 동일한 방식(비밀번호 기반)으로 수정·삭제할 수 있다.

### 1.1 목표

- 로그인/회원가입 없이 누구나 간편하게 글을 남길 수 있는 방명록 제공
- 비밀번호 기반의 본인 확인으로 글/답글의 수정·삭제 권한 보장
- 스팸 방지 기능 없이 단순하고 가벼운 구조로 구현 (운영 규모가 크지 않음을 전제)
- 부적절한 글이나 비밀번호 분실 상황에 대응할 수 있는 관리자 기능 제공

### 1.2 비목표 (Out of Scope)

- 회원가입/로그인/소셜 로그인 등 사용자 계정 시스템
- 캡차, 요청 빈도 제한(rate limit), 비속어 필터 등 스팸/악용 방지 기능 (요구사항 확인 결과 불필요로 결정됨)
- 답글의 답글(대댓글) — 답글 구조는 단일 계층으로 한정
- 좋아요, 알림(이메일/푸시), 검색 등 부가 기능

### 1.3 용어 정의

| 용어 | 설명 |
|---|---|
| 글(방명록 글) | 방명록에 최초로 작성되는 글 (게시글) |
| 답글 | 특정 글에 대해 다른 사용자가 남기는 댓글. 답글에 대한 답글(대댓글)은 지원하지 않음 |
| 작성자 비밀번호 | 글/답글 작성 시 사용자가 직접 설정하는 비밀번호로, 수정·삭제 시 본인 확인 용도로 사용 |
| 관리자 | 사이트 운영자. 별도의 관리자 인증 정보로 모든 글/답글을 비밀번호 없이 강제 삭제할 수 있음 |

| 유형 | 설명 |
|---|---|
| 방문자(비로그인) | 별도 인증 없이 이름/별명과 비밀번호만으로 글·답글 작성. 방명록 서비스의 주 사용자 |

## 3. 기능 요구사항

### 3.1 방명록 글 작성 (Create)

- FR-1.1 방문자는 로그인 없이 아래 항목을 입력하여 글을 작성할 수 있다.
  - 이름 또는 별명 (필수, 최대 20자)
  - 비밀번호 (필수, 수정/삭제 시 사용)
  - 비밀번호 확인 (필수, 비밀번호와 일치해야 함)
  - 본문 내용 (필수, 최대 500자)
  - 첨부 이미지 (선택, 최대 1장)
- FR-1.2 작성 시각(작성일시)은 시스템이 자동으로 기록한다.
- FR-1.3 필수 항목 미입력, 글자 수 초과, 비밀번호 불일치 등 유효성 오류 시 저장하지 않고 사용자에게 오류 메시지를 표시한다.
- FR-1.4 비밀번호는 평문으로 저장하지 않고 해시(예: bcrypt)하여 저장한다.

### 3.2 방명록 글 목록 조회 (Read)

- FR-2.1 방명록 글 목록은 최신 작성글이 상단에 오도록 정렬하여 보여준다.
- FR-2.2 글 목록은 페이지 단위로 나누어 보여주며(페이지네이션), 한 페이지당 노출 개수는 운영 설정 값으로 관리한다(기본값 예: 10개).
- FR-2.3 각 글 목록 항목에는 이름/별명, 본문 일부 또는 전체, 첨부 이미지(있는 경우) 썸네일, 작성일시, 답글 개수를 표시한다.
- FR-2.4 글 상세(또는 목록 인라인)에서 해당 글에 달린 답글 목록을 함께 확인할 수 있다.

### 3.3 방명록 글 수정 (Update)

- FR-3.1 목록/상세 화면에서 글마다 [수정] 버튼을 제공한다.
- FR-3.2 [수정] 클릭 시 비밀번호 입력을 요구하며, 작성 시 저장된 해시값과 일치할 때만 수정 화면으로 진입할 수 있다.
- FR-3.3 수정 화면에서는 이름/별명, 본문, 첨부 이미지를 변경할 수 있다. 비밀번호 자체는 이 기능에서는 변경 대상이 아니다.
- FR-3.4 수정 완료 시 수정일시를 별도로 기록하며, 목록/상세에 "수정됨" 표시를 노출한다.
- FR-3.5 비밀번호가 일치하지 않으면 수정할 수 없으며 오류 메시지를 표시한다.

### 3.4 방명록 글 삭제 (Delete)

- FR-4.1 목록/상세 화면에서 글마다 [삭제] 버튼을 제공한다.
- FR-4.2 [삭제] 클릭 시 비밀번호 입력을 요구하며, 일치할 때만 삭제가 진행된다.
- FR-4.3 삭제 전 확인(예: "정말 삭제하시겠습니까?") 절차를 거친다.
- FR-4.4 글을 삭제하면 해당 글에 달린 모든 답글도 함께 삭제된다. 이 사실을 삭제 확인 시 사용자에게 안내한다.

### 3.5 답글 작성 (Create)

- FR-5.1 방문자는 특정 글에 대해 로그인 없이 아래 항목을 입력하여 답글을 작성할 수 있다.
  - 이름 또는 별명 (필수, 최대 20자)
  - 비밀번호 (필수)
  - 비밀번호 확인 (필수)
  - 답글 내용 (필수, 최대 300자)
- FR-5.2 답글에는 이미지 첨부 기능을 제공하지 않는다 (원 글에만 첨부 허용).
- FR-5.3 답글은 원 글 하위에 작성 순(오래된 순 또는 최신 순, 운영 정책에 따름)으로 표시한다.
- FR-5.4 답글에 대한 답글(대댓글)은 지원하지 않는다.

### 3.6 답글 수정/삭제 (Update/Delete)

- FR-6.1 답글도 글과 동일하게 작성자 본인이 비밀번호 확인을 거쳐 수정·삭제할 수 있다.
- FR-6.2 답글 수정 시에도 수정일시를 기록하고 "수정됨" 표시를 노출한다.
- FR-6.3 답글 삭제 시 삭제 확인 절차를 거친다.
- FR-6.4 원 글이 삭제되어도, 답글은 원 글과 함께 자동 삭제된다(3.4 FR-4.4 참조).

### 3.7 관리자 기능

- FR-7.1 관리자는 별도의 관리자 인증(예: 관리자 비밀번호 또는 로그인)을 통해 관리자 모드로 진입할 수 있다.
- FR-7.2 관리자 모드에서는 모든 글/답글을 작성자 비밀번호 없이 강제로 삭제할 수 있다.
- FR-7.3 관리자 강제 삭제 시에도 삭제 확인 절차를 거친다.
- FR-7.4 (참고) 작성자가 비밀번호를 분실한 경우, 본인 확인 후 관리자에게 삭제를 요청하는 것을 기본 운영 방식으로 한다. 별도의 비밀번호 재발급/찾기 기능은 제공하지 않는다.

## 4. 비기능 요구사항

### 4.1 보안

- NFR-1.1 비밀번호는 반드시 해시(예: bcrypt, argon2)하여 저장하며, 평문 저장/전송을 금지한다.
- NFR-1.2 비밀번호 확인 로직(수정/삭제/관리자 삭제)은 클라이언트가 아닌 서버(백엔드) 측에서 검증한다.
- NFR-1.3 입력값에 대한 XSS/스크립트 삽입 방지를 위해 사용자 입력은 이스케이프 처리 후 저장/출력한다.
- NFR-1.4 이미지 업로드 시 허용 확장자(jpg, jpeg, png, gif, webp 등)와 최대 용량(예: 5MB)을 제한한다.
- NFR-1.5 관리자 인증 정보는 소스코드에 하드코딩하지 않고 환경변수 등으로 별도 관리한다.

### 4.2 사용성

- NFR-2.1 PC/모바일 브라우저 모두에서 자연스럽게 보이는 반응형 UI를 제공한다.
- NFR-2.2 필수 입력값 누락, 글자 수 초과, 비밀번호 불일치 등은 제출 전/후 즉시 안내한다.
- NFR-2.3 삭제와 같이 되돌릴 수 없는 작업은 반드시 확인 절차를 거친다.

### 4.3 성능

- NFR-3.1 목록 조회는 페이지네이션을 통해 한 번에 과도한 데이터를 불러오지 않도록 한다.
- NFR-3.2 이미지 첨부 파일은 적절히 리사이즈/압축하여 저장·서빙한다(선택 사항, 추후 개선 과제로 둘 수 있음).

### 4.4 데이터 보존

- NFR-4.1 삭제된 글/답글은 하드 삭제(완전 삭제) 또는 소프트 삭제(숨김 처리) 중 하나로 정책을 정한다. 기본안은 하드 삭제로 하되, 추후 운영 필요에 따라 소프트 삭제로 전환 가능하도록 설계를 열어둔다.

## 5. 데이터 모델 (초안)

### 5.1 posts (방명록 글)

| 필드명 | 타입 | 설명 |
|---|---|---|
| id | PK | 글 고유 ID |
| nickname | varchar(20) | 이름/별명 |
| password_hash | varchar | 해시된 비밀번호 |
| content | varchar(500) | 본문 내용 |
| image_url | varchar, null 허용 | 첨부 이미지 경로(URL). 미첨부 시 null |
| created_at | datetime | 작성일시 |
| updated_at | datetime, null 허용 | 수정일시. 수정 이력 없으면 null |

### 5.2 comments (답글)

| 필드명 | 타입 | 설명 |
|---|---|---|
| id | PK | 답글 고유 ID |
| post_id | FK → posts.id | 원 글 ID |
| nickname | varchar(20) | 이름/별명 |
| password_hash | varchar | 해시된 비밀번호 |
| content | varchar(300) | 답글 내용 |
| created_at | datetime | 작성일시 |
| updated_at | datetime, null 허용 | 수정일시 |

> 참고: 원 글(post) 삭제 시 하위 답글(comments)도 함께 삭제되도록 외래키 `ON DELETE CASCADE` 적용을 권장한다.

## 6. 화면 요구사항 (초안)

1. **방명록 목록 화면**
   - 글 목록(최신순, 페이지네이션)
   - 글쓰기 버튼/폼 진입점
   - 각 글에 [수정]/[삭제] 버튼, 답글 개수 및 답글 목록/작성 폼 진입점
2. **글쓰기 폼**
   - 이름/별명, 비밀번호, 비밀번호 확인, 본문, 이미지 첨부(선택)
3. **글 수정 폼**
   - 비밀번호 확인 단계 → 통과 시 이름/별명, 본문, 이미지 수정 가능
4. **답글 영역** (글 상세 또는 목록 인라인)
   - 답글 목록, 답글 작성 폼, 답글별 [수정]/[삭제]
5. **비밀번호 확인 모달/다이얼로그** (수정·삭제 공통)
6. **삭제 확인 모달/다이얼로그** (글/답글 공통, "답글도 함께 삭제됩니다" 안내 포함)
7. **관리자 화면**
   - 관리자 인증(로그인 또는 비밀번호 입력)
   - 전체 글/답글 목록 + 비밀번호 없이 강제 삭제 가능한 [삭제] 버튼

## 7. 확정된 요구사항 결정 사항 (Q&A 요약)

아래는 문서 작성 전 확인한 주요 결정 사항이다.

| 항목 | 결정 내용 |
|---|---|
| 구현 형태 | 정적 사이트 + 간단한 백엔드(API 서버) + DB 조합 |
| 답글 구조 | 단일 계층 (답글의 답글은 지원하지 않음) |
| 스팸/악용 방지 | 캡차, 요청 제한, 비속어 필터 등 도입하지 않음 |
| 비밀번호 분실/부적절한 글 대응 | 관리자가 비밀번호 없이 강제 삭제 가능 |
| 첨부파일 | 글에 이미지 1장 첨부 허용 (답글은 미지원) |
| 목록 표시 방식 | 최신글이 위, 페이지네이션 방식 |
| 글자 수 제한 | 닉네임 20자, 본문(글) 500자, 답글 300자 |

## 8. 향후 논의가 필요한 사항 (Open Issues)

- 이미지 저장 위치: 로컬 파일 시스템 vs. 클라우드 스토리지(S3 등)
- 하드 삭제 vs. 소프트 삭제 정책 최종 확정
- 관리자 인증 방식 구체화 (단순 비밀번호 입력 vs. 별도 로그인 세션)
- 실제 배포 환경(호스팅) 및 구체적인 기술 스택(프레임워크, DB 종류) 선정
- 답글 정렬 순서(오래된 순/최신 순) 확정
